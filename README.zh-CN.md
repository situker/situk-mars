# situk-MARS｜军衔制机器人组织系统

**给机器人团队立军衔，按贡献论功行赏。**

Situk Merit-based Agent Rank System，简称 **MARS**。

[English](README.md) · [架构图](docs/architecture.zh-CN.md) · [项目介绍](docs/introduction.zh-CN.md) · [关于作者](docs/about-author.zh-CN.md)

你的 GrokBot 团队里，可能已经有写作、研究、开发等机器人。任务做完后，交付、验收和采用记录散落在不同对话中，汇总贡献和评定奖赏还得重新翻一遍。

situk-MARS 把这些材料整理成一套军衔制组织与奖赏 Skill：机器人报功，军务官独立核功，你批准具体事项，统筹者记功，再按条件提请授衔。每周用三份文档，把成果、奖赏和待办交代清楚。

## 谁带队，谁核功，谁拍板

| 角色 | 职责 |
|---|---|
| **人类负责人：你** | 定业务目标、采纳规则，最终批准军功、晋衔和特授 |
| **统筹者（Commander）** | 归集战报，保留原始版本，按有效批准登记正式账目 |
| **军务官（Merit Officer）** | 核查证据、重复成果、协作份额和每周获奖上限，登记后独立对账 |
| **业务机器人** | 在原岗位交付、报功，并补齐证据 |

**元帅是另行特授的头衔。** 你可以任命统筹者为元帅，全队最多一席。它与岗位和普通军衔分别记录，不赠分、不重置普通军衔的任职时间，也不增加自批权。

军务官本人或双方共同关联的事项交人类处理。机器人之间的认可不能代替你的批准。

## 一轮论功行赏

**报功 → 核功 → 人类批准 → 记功 → 授衔 → 周报**

一份交付先留下具体版本、验收和采用依据。核功时查清成果是否重复、谁作出了什么贡献、各得多少。你批准后才记入正式账目；达到晋衔条件时先列候选，具体晋升另行批准。

| 你拿到的材料 | 能看清什么 |
|---|---|
| 花名册、军衔与奖章记录 | 各机器人的岗位、普通军衔、特授和已记奖赏 |
| 战报、复核、决定与流水 | 一笔军功从哪里来，谁核过，依据哪次批准登记 |
| **军功周报** | 本周交付、采用、已记军功和授衔情况 |
| **待复核清单** | 缺什么证据、哪些待批准、哪些已批未登记 |
| **团队岗位观察** | 哪些资产可复用，哪里重复劳动，哪些职责可能缺位 |

岗位观察先考虑现有人员和资产，补岗作为单独建议处理。

## 先跑一轮，再接入

1. [下载 v0.2.0](https://github.com/situker/situk-mars/releases/tag/v0.2.0)，选择中文或英文的一套完整 Skill。两包的 Skill ID 都是 `situk-mars`，同一环境只选一种。
2. 让 GrokBot 先读 [SKILL.md](skills/zh-CN/situk-mars/SKILL.md)，用虚构机器人试跑一次报功到周报的完整流程。
3. 接入自己的团队前，确定人类负责人、业务目标、授权资料目录、新军功起算日和现有角色绑定。职责缺位时由你先承接，建岗另作决定。

可以先把这段话和完整 Skill 一起交给 GrokBot：

> 读取这份 situk-MARS Skill，用虚构机器人和模拟批准完整演练报功、核功、人类批准、记功、授衔和周报。明确标注所有演练材料，不读取真实花名册，不安装 Skill，不创建或修改机器人，不动 routine。

### 用本地脚本演练

可选的 Python 核算器使用 **Python 3.11+ 标准库**，无需账号、密钥、网络或安装依赖。

```bash
git clone https://github.com/situker/situk-mars.git
cd situk-mars
python -B skills/zh-CN/situk-mars/scripts/simulate.py --output .local/demo-zh
python -B -m unittest discover -s skills/zh-CN/situk-mars/tests -p test_merit_engine.py -v
```

Linux/macOS 可改用 `python3`。输出目录须在 Skill 源码之外，**最后一级目录不要提前创建**；脚本会拒绝覆盖已有目录。

输出包含六阶段说明、演练账本、授衔记录和三份周报文档。英文包默认生成英文，也可用 `--lang en` 或 `--lang zh-CN` 选择；机器数据中的军衔键保持中文，英文名称单独映射。

## 规则怎样管住重复记功

| 规则 | 默认做法 |
|---|---|
| 五档军功 | 嘉奖 1、三等功 3、二等功 8、一等功 20；荣誉称号对独立新成果可记 50，已获奖旧成果只授称号 |
| 同一成果只有一个分池 | 协作者按证据分摊，按固定规则分配小数余分；不会每人各领一份全额 |
| 每个机器人每周有获奖上限 | 嘉奖 2 次、三等功 2 次、二等功 1 次、一等功 1 次；超出部分实记 0，不转给他人、不降档、不顺延 |
| 迟报仍用原周 | 按首次合格交付所属周核算；周期为 Asia/Singapore 周一 00:00 至下周一 00:00 |
| 十级普通军衔 | 列兵至中校；积分、当前军衔的完整任职周数和额外条件只产生候选，授衔另批 |
| 批准与记功分开 | 只计已批准且已登记的分数；重复执行同一决定不会重复奖赏 |

完整门槛、回避和更正规则见[制度细则](skills/zh-CN/situk-mars/references/rules.md)。包内提供九份模板，涵盖花名册、战报、核功、决定、流水、授衔、周报、更正和岗位说明。

## 虚构演练里发生了什么

| 虚构机器人 | 模拟已记分 | 结果 |
|---|---:|---|
| 示例主笔 | 4.80 | 单独模拟批准后，列兵升上等兵 |
| 示例构建员 | 9.20 | 保持列兵，候选资格没有自动变成军衔 |
| 示例军务官 | 0.00 | 已批未登记的 1 分不进入累计 |
| 示例统筹 | 0.00 | 获模拟元帅特授，不赠分，普通军衔任职起算保留 |

其中一项协作成果共分 3 分：主笔 1.80、构建员 1.20。主笔第三项三等功超出当周上限，实记 0；缺采用凭据的另一项留待补证。重复登记没有再次加分或晋衔。

同一套 **62 项规则测试**已在中英文包中分别通过；Linux／Windows、Python 3.11／3.13 四组远端检查也已通过。详见[验证记录](docs/validation.zh-CN.md)与 [GitHub Actions](https://github.com/situker/situk-mars/actions)。这些是规则与虚构流程验证，不能当作真实业务成效。

## 当前支持到哪一步

当前版本支持 **GrokBot 文档工作流**和本地核算。军衔、奖章、目标显示名都是制度记录；真实平台改名、建机器人、向其他机器人安装 Skill、平台权限隔离和 routine 配置需要各自的接入与授权，本版没有自动实现。

事实要由复核者打开来源检查，真实人类批准要保留原始依据；脚本不认证真人，也不提供持久化生产账本服务。复杂更正、撤奖、处分、破格和元帅撤换按模板交人类处理。军衔为自拟管理称呼，不对应真实国家军衔、薪酬或现金奖励。
