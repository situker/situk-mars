# situk-MARS｜军衔制机器人组织系统 · 中文 Skill

作者：司徒K · [www.situking.com](https://www.situking.com)

**给机器人团队立军衔，按贡献论功行赏。**

这套 Skill 面向 GrokBot 团队，把交付、验收和采用记录整理成军功提案，经人类批准后记功、授衔，再用周报说明本周成果和待决定事项。

统筹者（Commander）归集报功、登记已批准事项；军务官独立核功和对账；人类负责人保留最终批准权。元帅是可由人类另行特授的头衔，与统筹岗位、普通军衔分别记录。

本包采用 0.2.0 规则，与英文包共用 Skill ID `situk-mars`。每个运行环境选择一种语言包，不同时安装两版。

```mermaid
flowchart LR
  A[报功：交付、验收与采用证据] --> B[核功：查重、分摊、每周上限与回避]
  B --> C[人类批准具体条目]
  C --> D[记功：唯一登记与独立对账]
  D --> E[授衔：候选另经批准]
  E --> F[周报：已记、待核、待拍板]
```

| 制度 | 默认规则 |
|---|---|
| 军功 | 嘉奖 1、三等 3、二等 8、一等 20；荣誉仅对独立新成果计 50，已获奖成果只授称号 |
| 每周上限 | 一事一档、归属原周；每人每周嘉奖 2 次、三等 2 次、二等 1 次、一等 1 次 |
| 协同 | 同一个分池按证据分摊；超帽份额不转给别人、不降档、不顺延 |
| 普通军衔 | 列兵至中校 10 级；积分、当前军衔的完整任职周数和额外条件只产生候选，具体晋衔另批 |
| 元帅 | 人类特授 0–1 席，不加分、不重置普通军衔的起算时间、不增加自批权 |
| 奖章与名称 | 榜单用“🏅＋文字等级”；目标名为“原名〔正式军衔〕”，不堆叠后缀 |
| 周报 | 军功周报、待复核清单、岗位观察；默认手动，不创建任何调度 |

## 开始使用

把完整 Skill 文件夹交给 GrokBot，先读 [SKILL.md](SKILL.md)。数值源为 [policy.json](policy.json)，表格在 [templates/](templates/)。

首次使用需指定人类负责人、业务目标、已授权资料目录、新功起算时间和角色绑定。优先沿用现有统筹者和无关联核验者，缺位职责由人类承接；是否创建岗位另行处理。采纳制度不等于批准具体奖赏、授衔或平台动作。

## 本地跑一轮虚构演练

从本 Skill 目录执行：

```powershell
python -B scripts/simulate.py --output ../.local/my-merit-demo
python -B -m unittest discover -s tests -p test_merit_engine.py -v
```

Python 3.11+ 标准库即可，无需安装依赖、联网或账号。没有 python 命令时可用 python3。输出必须是 Skill 源码之外的新目录；不要预建最终目录，空目录也会被拒绝，已有目录不会重置。

演练读取固定虚构输入，生成六阶段说明、合成证据索引、模拟批准、演练账本、授衔记录和三份周报样例。默认输出中文，也可通过 `--lang en` / `--lang zh-CN` 选择文档语言。

预期结果为：主笔 4.80 分，经单独模拟批准升上等兵；构建员 9.20 分，仍为列兵；主笔第三份三等功超周帽记 0。军务官本人事项转模拟人类核定，已批准但未登记的 1 分不计入累计。统筹者获模拟元帅特授，赠送分为 0。名字只生成待同步目标，真实平台改名动作 0。

## 核算与执行边界

引擎辅助算分、检查上限、去重、登记和候选核对，**不验证事实真伪、不认证真人，也不是持久化生产账本服务**。`READY` 只表示字段和规则检查足以形成提案，不代表真实证据已认证。真实使用仍须军务官打开授权来源核验，保留人类原始批准，按模板追加正式文档，再独立对账。

复杂更正、撤奖、处分、破格和特授撤换使用人工模板，脚本未自动实现。0.2.0 规则数值保持固定；定制须形成新规则版本，并经人类采纳。岗位说明是行为约束，不能当作已验证的平台 ACL（访问控制）。本包不自动创建机器人、安装 Skill、修改真实名字或配置 routine。
