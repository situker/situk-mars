# situk-MARS｜军衔制机器人组织系统 · 中文 Skill

作者：司徒K · [www.situking.com](https://www.situking.com)

0.2.0 制度发布版。这是一套可交给 GrokBot 执行的通用 Skill，用交付、采用和业务结果证据评价机器人贡献，由人类批准军功与晋衔。统筹岗位（Commander）归集报功并按批准登记，军务官负责独立核验和周报；元帅是另行特授的头衔。

```mermaid
flowchart LR
  A[报功：交付与采用证据] --> B[核功：查重、分摊、周帽、回避]
  B --> C[人类批准具体条目]
  C --> D[记功：唯一登记与独立对账]
  D --> E[授衔：候选另经批准]
  E --> F[周报：已记、待核、待拍板]
```

| 制度 | 默认规则 |
|---|---|
| 军功 | 嘉奖1、三等3、二等8、一等20；荣誉独立新成果50，旧成果仅授称号 |
| 防通胀 | 一事一档、原周归属；个人每周嘉奖2次、三等2次、二等1次、一等1次 |
| 协同 | 同一个分池按证据分摊；超帽份额不转给别人、不降档、不顺延 |
| 普通军衔 | 列兵至中校10级；积分、完整在阶周和额外条件只产生候选，具体晋衔另批 |
| 元帅 | 人类特授0–1席，不加分、不重置普通轨时间、不增加自批权 |
| 奖章与名称 | 榜单用“🏅＋文字等级”；目标名为“原名〔正式军衔〕”，不堆叠后缀 |
| 周报 | 军功周报、待复核清单、岗位观察；默认手动，不创建任何调度 |

制度入口是 [SKILL.md](SKILL.md)，数值源是 [policy.json](policy.json)，表格在 [templates/](templates/)。完整目录可单独交给 GrokBot，无需携带0.1.0部署原型。首次使用先配置人类负责人、目标、已授权资料目录、新功起算和角色绑定；沿用已有角色，缺位时人类承接，建岗另行处理。

本地完整演练：从本 Skill 目录执行：

```powershell
python -B scripts/simulate.py --output ../.local/my-merit-demo
python -B -m unittest discover -s tests -p test_merit_engine.py -v
```

Python 3.11+ 标准库，无需安装依赖、网络或账号。没有 python 命令时可用 python3；不要预建最终输出目录，空目录也会被拒绝。输出必须是 Skill 源码之外的新目录，已有目录不会重置。演练只读固定虚构输入，生成六阶段说明、合成证据索引、模拟批准、正式模拟账、授衔记录和三份周更样例。

练习的结果是：主笔4.80分，经单独模拟批准晋上等兵；构建员9.20分，仍为列兵；主笔第三份三等功超周帽记0；军务官本人事项转模拟人类核定，已批准但未登记仍0分。统筹获模拟元帅特授，赠送分0。目标显示名只生成待办，真实平台改名动作0。

引擎辅助算分、查帽、去重、登记和候选检查，**不验证事实真伪、不认证真人，也不是持久化生产账本服务**。`READY`表示字段及规则可形成提案，不代表真实证据已认证。真实使用仍需军务官打开来源核验，保留人类原始批准，按模板追加正式文档，并独立对账。

复杂更正、撤奖、处分、破格、特授撤换保留完整人工模板流程，脚本未自动实现。规则数值固定于0.2.0，定制需新规则版本与人类采纳。GrokBot的角色说明只作行为约束，不承诺平台ACL或真实自动建岗。
