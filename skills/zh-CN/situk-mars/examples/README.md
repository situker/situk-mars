# 虚构练习输入

`synthetic-reports.json` 是固定练习输入，不是运行结果。四位角色 ID `demo_writer`、`demo_builder`、`demo_commander`、`demo_officer` 均为虚构。所有 `synthetic://` 指针都是说明性占位符，无法证明真实交付、采用、复用或人类批准，不得复制到实际军功账。

建议模拟配置：新功起算 `2026-10-12T00:00:00+08:00`；四位角色同期入列、普通衔列兵；普通在阶起算同上；业务目标为“让虚构服务交付过程更完整、可核对”。终审观察时间使用 `2026-10-26T10:00:00+08:00`，原周期 `2026-W43` 已闭合。元帅岗位特授仍须模拟人类另作决定，岗位名不等于已授元帅。

| 顺序 | 场景 | 在人类模拟逐项批准并由元帅登记后的预期 |
|---|---|---|
| 1 | 主笔已采用、目标链完整的三等功 | 主笔 +3.00 |
| 2 | 构建员的稳定资产已在第二独立任务复用 | 构建员 +8.00 |
| 3 | 主笔 60%、构建员 40% 的同成果三等功 | 主笔 +1.80，构建员 +1.20，合计 3.00 |
| 4 | 主笔同周第三次三等功申请 | 贡献保留，名义 3.00，超帽实记 0.00 |
| 5 | 自报采用但缺采用凭证 | NEEDS_EVIDENCE，不批准、不入账，不自动降奖 |
| 6 | 军务官本人申请嘉奖 | 不能自核，转人类；未批准登记前不计分 |

前四条顺序处理后，正式分预期为主笔 4.80、构建员 9.20，元帅与军务官均 0.00。第六条若再由模拟人类核定、批准并登记，则军务官增加 1.00，但独立对账继续交模拟人类，不由军务官自己验收。

二等功示例分别提供 `reuse_task_id`、`reuse_ref` 与 `reuse_acceptance_ref`，证明的事项依次是第二独立任务、实际复用、该任务复用结果的验收。原资产验收不能代替第二任务的验收；三个字段的凭据在本例中均为虚构。

晋衔演练只能提出候选：主笔若同时满足至少 1 个完整在阶周期、合格交付、下一阶已批准职责要求及其验收，可提列兵至上等兵。候选本身不改军衔；模拟人类批准后由元帅登记，名字只生成待同步目标，不调用真实平台。

运行器必须把实际演练日志、批准模拟、账本、花名册及周报写到项目的 `.local/` 运行位置，不能写回本目录。本地操作者提供的 owner 身份和 `synthetic://` 批准记录只是模拟声明，不是真人人脸、签名或平台消息认证。
