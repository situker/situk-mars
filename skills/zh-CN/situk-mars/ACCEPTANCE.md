# 0.2.0 制度验证记录

日期：2026-10-26（Asia/Singapore）。本页记录发布前的本地验证，当前开源许可与发布状态以仓库 README 和 LICENSE 为准。结论：**通用 Skill 已整理，虚构军功制度主链已跑通。** 这不是 GrokBot 真实部署或真实奖赏记录。

本页记录的原验证阶段仅覆盖本地制作与模拟报功/核功/批准/记功/授衔/周报，当时未发布，未动现有机器人和 routine。后续仓库发布是独立的分发动作；该包没有联网、机器人管理、消息或调度调用。

## 规则来源及通用化

基于已有v1.4-review.1修订稿的规则，保留证据门槛、五档分池、个人原周帽、协同分币守恒、回避、人类具体批准、唯一登记、普通轨完整在阶周期、元帅单席零赠分、命名及周报。

用空白通用模板和虚构例子重建，没有复制真实花名册、机器人ID、个人目标、账户指标、批准记录、原运行路径或历史账。数值和规则明确为客户采纳后适用，不能假设作者私人制度已在客户环境生效。

## 自动化验证

`python -B -m unittest discover -s tests -p test_merit_engine.py -v`：**62项全部通过，0跳过、0失败**。测试覆盖证据、原周期、分池、周帽、回避、同榜同人多事件、批量帽、批准篡改、未知目标、晋衔时间、下阶职责验收、元帅及周报。

最终源码对应的三次独立完整模拟均为SIMULATION_PASSED，六阶段全部通过，结果一致。静态precheck为0错误、0警告；扫描25个源码/模板文件无已知私人标记、私人绝对路径或断开的Markdown链接。描述计数241个历史代理单位仅是本地静态指标，不是宿主运行时占用证明。

独立复核发现并修复：批量提案需要按整榜shadow核帽；null目标不能转成字符串冒充已配置；人类对账后旧回避队列应解除；晋衔批准须封存完整内容；当前态不能使用未来分倒签；缺交付版本的自报不能凑满近期合格交付。

单独核功的多个提案若合成整榜导致帽变化，会原子拒绝而不悄悄改批准。正常整榜应使用review_batch返回的顺序与名义/实记提案，再批准同一决定各事项，最后一次post；同一人多事件entry互不误吞。

## 六阶段合成演练

| 阶段 | 验证内容 |
|---|---|
| 报功 | 6条虚构战报，稳定事件、原周、具体交付、采用及协同字段 |
| 核功 | 缺采用凭据待补；军务官本人事项转模拟人类；两人只分一个3分池 |
| 批准 | 绑定确切提案/事项/账本版本/有效期；模拟批准不是真实人类证据 |
| 记功 | 4个事件共5条个人分录；主笔4.80，构建员9.20；超帽名义3实记0 |
| 授衔 | 主笔达到候选条件后仍是列兵，单独模拟批准后才升上等兵；重复不重授 |
| 周报 | 已批未登记1分不进正式总分；输出军功周报、待复核清单、岗位观察 |

军功归属2026-W43；在闭合后的W44结算和授衔，不伪记为W43已经晋升。普通军衔当前阶时间重新起算；元帅特授不重置普通轨，不赠军功。

所有真实平台动作、改名、机器人改动、routine改动和发布均为0。显示名状态是NAME_SYNC_NOT_EXECUTED；不能将名册目标名当平台实际名。

## 实现边界

Skill可用文档与模板完成制度流程，不要求先打通完整Bot API。脚本只是确定性核算辅助和虚构模拟，不是自动事实核验、真人认证、不可篡改审计或持久化生产服务。共享宿主下的岗位说明不构成系统权限隔离。

复杂更正、撤奖、处分、破格和特授撤换按模板人工逐项批准及追加；脚本不自动执行。本仓库按 LICENSE 开源；以下测试未安装到真实环境。验收是本地开发验证，尚不是用户对真实业务运行的验收。
