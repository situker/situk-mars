# 人类逐项批准单模板

由统筹者汇总确切提案后填写草案，交人类负责人审阅、逐项决定。初始状态为 `DRAFT_FOR_HUMAN`，只有取得可核对的人类明确批准，才能转为 `HUMAN_APPROVED`。AI 生成表格、填写人类姓名或整理批准摘要，都不是实际批准。

- `decision_id`：<稳定唯一 ID>
- `board_version` / `rule_version`：<准确版本>
- `content_hash`：<批准事项规范化后的内容 hash>
- `approval_ref`：<人类原始批准消息/签署记录；模拟另标 synthetic>
- `approved_by` / `approved_at`：<人类标识 / 含时区>
- `valid_from` / `valid_until`：<授权可登记区间；不得无限期沿用旧批准>
- `effective_at`：<事项生效时点，含时区>
- 人类批准范围：<逐项 ID / 本版本全部已明列事项>
- 已看见的回避项：<统筹者、军务官本人、共同受益等>
- 本轮模式：<LOCAL_SIMULATION / 经另行授权的实际执行>

| `approved_item_id` | 动作 | `event_id` / 原周期 | 对象稳定 ID | 等级/名义比例/确切实记或军衔席位 | 依据与复核 ID | 明确结论 |
|---|---|---|---|---|---|---|
| <稳定事项 ID，不用行号> | <记功/更正/晋衔/特授> | <事件/周期> | <ID> | <完整批准值> | <指针> | <批准/拒绝/待补> |

记功项目须附完整参与者、比例、名义份额、每周上限（周帽）和实际入账；整榜批准必须明确覆盖这些细项。晋衔项目须附原衔、目标衔、下一阶验收与席位条件。元帅特授须附唯一席位、承接普通军衔及任免时序。

登记前核对：批准原记录确实来自人类，hash 与待执行内容一致，未过期，规则和作用域一致，稳定 ID 唯一，正式账读前版本未改变。内容变化、字段缺失、证据改变或批准无法定位时，停止相应项，统筹者不能自行解释补齐。沉默、“收到”“看起来不错”不算对具体授奖的批准。

批准军功不等于批准改名、扩权、发消息、发布、建岗或 routine。本地模拟只更新虚构资料，本版不执行真实改名。今后即使接入后缀同步，也只能针对已批准军衔、已授权对象和确切后缀执行，不能扩大到其他 profile 字段。
