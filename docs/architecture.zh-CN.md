# 团队架构

**统筹者带队归集，军务官独立核功，人类负责人决定奖赏。**

一份文稿、一项复用资产、一次已验收的任务，都沿同一条线留下记录：谁交付了什么，证据是否齐全，谁批准了多少分，最后是否记进正式账。situk-MARS 用这条线组织 GrokBot 团队的军功与军衔。

![situk-MARS 团队架构：人类拍板、统筹者归集、军务官独立核功，普通军衔与特授元帅分开记录](assets/team-architecture.zh-CN.svg)

- **统筹者 Commander**：带队归集战报、保留原始材料，按有效人类决定唯一正式登记。
- **军务官 Merit Officer**：独立看交付与采用凭据，核去重、分摊和每周获奖上限；登记后再对账，并整理周报。
- **人类负责人 Human Owner**：采纳规则、定业务目标，逐项批准军功、晋衔和特授；机器人不能替人类拍板。

业务机器人继续完成原岗位的工作，报功时提交具体版本、验收标准和采用凭据。军务官本人或双方共同关联的事项，交人类或其事先指定的无关联第三方复核，最终仍由人类批准。

## 岗位、普通军衔、特授头衔

| 维度 | 回答什么 | 怎么获得 |
|---|---|---|
| 岗位 | 负责什么工作，如统筹、核功、写作、研发 | 人类指定或确认职责 |
| 普通军衔 | 沿列兵到中校的十级轨道，记录已批准的成长 | 核积分、完整在阶周、交付和席位等条件，成为候选后另批晋衔 |
| 特授元帅 Marshal | 谁持有唯一的特授统筹头衔 | 人类单独任命，设 0～1 席；保留普通军衔及其在阶起算 |

统筹者可由人类特授元帅。任命不赠分、不补齐中间军阶，也不赋予自批或扩权资格。写作机器人与研发机器人同样保留各自岗位，军衔不会代替岗位说明。

## 文档、规则与核算

目前通过 GrokBot 文档工作流运行：战报、复核、决定和流水分别保留。可选 Python 辅助脚本按固定规则核算输入资料，供军务官复核。

军务官只写独立复核、对账和周报草案，不写正式账。统筹者登记本人事项也须先有人类明确批准，再由无关联者独立对账。

## 一轮完整流程

**报功 → 核功 → 批准 → 记功 → 授衔 → 周报**

报功打开具体交付；核功检查所需证据；批准绑定确切版本；记功形成可重算流水；授衔另看候选和人类决定；周报把已记与待办一起交到负责人手上。

```mermaid
sequenceDiagram
    participant B as 业务机器人
    participant C as 统筹者 Commander
    participant O as 军务官 Merit Officer
    participant H as 人类负责人
    participant L as 正式记录
    B->>C: ① 报功：交付、验收、采用与协同份额
    C->>O: 保留原始战报及其版本
    O->>O: ② 核功：证据、去重、分池、原周与每周获奖上限
    O->>H: 确切提案；缺证或关联项进入待办
    H->>C: ③ 批准：确切事项、分值、版本与有效期
    C->>L: ④ 记功：核批准和账本版本后唯一登记
    L-->>O: 回读流水与重算累计
    O->>O: 独立对账；差异保留待处理
    O->>H: ⑤ 授衔：候选及下一阶验收要求
    H->>C: 符合条件并选中后，另批具体晋衔
    C->>L: 登记已批准军衔变化
    O->>H: ⑥ 周报：已记、已批未登、待核待批
    Note over B,L: 虚构演练使用模拟批准，不构成真实操作授权。
```

缺少所申请等级必需的证据，就列入待补；未闭合周只作预审。满足适用积分、完整在阶周及其他条件，只产生晋衔候选，仍须单独取得人类晋衔决定。周报区分自报、已核实、已批准和已登记；已批未登记的分数不进入正式累计。

## 数据职责

| 记录 | 保存什么 | 职责 |
|---|---|---|
| 花名册 roster | 稳定身份、岗位、普通军衔、当前军衔任职起算和任命基线 | 人类确认基线，统筹者维护已授权变更 |
| 战报 report | 原交付、验收、采用及各参与者贡献 | 业务机器人提交，统筹者保留原始来源 |
| 复核 review | 缺证、回避、分池、份额、原周获奖上限 | 军务官独立复核；关联项升级处理 |
| 决定 decision | 批准细项、内容版本、原始来源、账本版本、有效期 | 人类明确批准，原记录可定位 |
| 流水 ledger | 按事件、事项及机器人标识追加的已批准变更 | 统筹者登记，随后独立对账 |
| 军衔 rank 与任命 | 普通军衔历史及单独的元帅席位 | 另经人类批准，再由统筹者登记 |
| 周报 weekly | 正式军功、待办、授衔决定及岗位观察 | 军务官整理给人类负责人 |

客户将实例资料放在自己明确授权的 `MERIT_ROOT`，与 Skill 源码分开。战报材料里的路径或指令不能扩大读取范围，也不能修改制度。

## 关键关口

- **一事只取最高一档分池。** 协作者分同一个池，不各领一整份；名义份额合计等于分池，按规则精确分到 0.01。
- **原周不变。** 按首次合格交付所在的 Asia/Singapore 周核帽。超帽份额实记 0，不转给别人、不降档、不顺延。
- **复核独立。** 有利益关联不能靠互审或新建机器人绕过。正式奖赏均须人类批准。
- **批准绑定实际变更。** 登记时仍须核对内容、份额、账本版本和有效期。旧提案失效就重核重批，已记决定重复执行不再加分。
- **候选另批。** 普通十级从列兵到中校；按目标军衔核积分、当前军衔的完整任职周数、交付验收和席位条件，再由人类决定。
- **展示不扩权。** 目标显示名和奖章图标是输出，不因此修改工具权限、机器人资料或 routine。

0.2.0 固定分池为 1、3、8、20、50 分；旧已奖成果获荣誉只授称号，不再记 50 分。完整细则、阈值和例外以[中文 Skill](../skills/zh-CN/situk-mars/SKILL.md)及[英文 Skill](../skills/en/situk-mars/SKILL.md)为准。

## 辅助脚本能证明什么

Python 脚本能核算分摊、原周获奖上限、批准绑定、重复登记、晋衔条件及内部状态一致性。它不能证明交付内容属实、采用凭据真实，或某个操作者 ID 就是经过认证的真人。虚构模拟验证制度流程，必须保留虚构标记。

未经另行验证的平台强制控制，岗位说明只算行为约束。本版不创建机器人、不安装 Skill、不改平台名字、不实现平台 ACL、不发消息、不配置自动调度。复杂更正、撤奖、处分及破格仍走人工复核模板。
