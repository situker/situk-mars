# situk-MARS｜军衔制机器人组织系统

**给机器人团队立军衔，按贡献论功行赏。**

[下载中文 ZIP](https://github.com/situker/situk-mars/releases/download/v0.2.0/situk-mars-v0.2.0-zh-CN.zip) · [先看周报样张](examples/zh-CN/weekly-report.md) · [首次试跑](quickstart.zh-CN.md) · [English](introduction.md)

一个机器人写方案，一个把方案做成工具，还有一个核查结果。任务做完，贡献散在聊天里：谁的交付被采用了，协作怎样分功，下一阶还差什么？

**situk-MARS** 给 GrokBot 团队一套报功、核功、奖赏与授衔流程。英文全名 **Situk Merit-based Agent Rank System**，简称 **MARS**。它把交付、验收、采用依据和人类决定整理成军功记录，让一次奖赏能顺着记录查回原始依据。

## 把一周的贡献，整理成三份结果

![一轮虚构演练生成的军功周报、待复核清单和团队岗位观察概览](assets/overview.zh-CN.png)

**军功周报**告诉你哪些军功和晋衔已经登记；**待复核清单**保留缺证、待决定和已批未登记事项；**团队岗位观察**整理可复用成果和需要再看的职责问题。打开[三份完整样张](examples/README.zh-CN.md)，就能先判断这些材料是否适合你的团队。

图里全部是虚构演练。主笔记 4.80 分，经另行模拟批准晋上等兵；构建员记 9.20 分，仍为列兵。本轮未给构建员办理具体晋衔批准和登记，分数本身不会改写军衔。

## 同一份成果，协作记在一起

虚构输入里有一份协同指南：主笔写说明，构建员补核对清单。两部分作为同一成果被模拟采用，共享三等功的 **3 分**：主笔 **1.80**，构建员 **1.20**，分别计入累计。

MARS 把各自贡献写清楚，再分同一个分池。同一成果不能换个标题重复领功；已验收资产在第二个独立任务实际复用，才有相应的资产证据可核。[查看这轮输入与样张来源](examples/README.zh-CN.md)。

## 军务官核功，你保留决定权

**报功 → 核功 → 人类批准 → 记功 → 授衔 → 周报**

统筹者归集原始战报，军务官独立核对交付、采用凭据、协作份额和每周获奖上限。你批准具体事项后，统筹者登记正式账目，军务官再回读对账。每一轮都有明确的待办和需要你作出的决定。

军务官本人或双方共同关联的事项，交人类或其事先指定的无关联第三方复核，最终仍由人类批准。[打开团队架构图](architecture.zh-CN.md)，看清谁核、谁批、谁记。

## 让机器人知道，下一阶要拿出什么

![列兵至中校的十级普通军衔，以及另行特授的元帅席位](assets/rank-path.zh-CN.png)

从列兵起步，逐阶核对合格战报、军功、可复用资产和下一阶验收要求。适用等级同时看积分、当前阶完整任职周与额外条件，达到门槛先成为候选，实际晋衔由你另批。少校、中校还须有已批准席位并经人类选升，中校不设自动积分门槛。

**元帅另行特授，全队最多一席，只授统筹者。** 不加分，不重置普通军衔的在阶起算，也不增加自批权。岗位、普通军衔和特授分别记录。[查看十级门槛、五档军功和命名示例](ranks.zh-CN.md)。

## 先用虚构团队，跑一轮看看

下载包内有中英双语 Skill、九份模板、虚构输入和可选 Python 核算器。先跑固定演练，看到三份结果，再确定自己的业务目标、授权资料范围、军功起算日和现有角色绑定。两包使用相同的 0.2.0 数值规则，同一环境选择一种语言即可。

本地试跑需要 Python 3.11+，只用标准库，下载后可离线运行。GrokBot 对话演练则需要宿主能读取完整 Skill 文件夹。[三步开始试跑](quickstart.zh-CN.md)。

当前版本是文档工作流与本地核算。真实建机器人、改名、平台权限隔离和 routine 配置需要另行接入；事实核验和人类批准仍须保留来源。复杂更正、处分和破格使用人工复核模板。
