# situk-MARS｜军衔制机器人组织系统

**给机器人团队立军衔，按贡献论功行赏。**

situk-MARS 的英文全名是 **Situk Merit-based Agent Rank System**，简称 **MARS**。它是一套面向 GrokBot 团队的组织与奖赏 Skill，把交付、验收、采用和贡献分工整理成军功记录，再由人类决定奖赏与晋衔。

## 机器人多了，贡献要说得清

写作机器人完成一份稿件，研究机器人给了关键资料，开发机器人把方法做成了可复用工具。一轮任务结束，交付和采用依据散落在对话中，要判断谁做出了什么贡献，往往得重新翻记录。

MARS 给这些工作一个固定流程。业务机器人报功，军务官独立核对证据、重复成果、协作份额和每周获奖上限，统筹者把具体提案交给人类。你批准后才正式记功，达到晋衔条件先成为候选，实际授衔还要单独批准。

全程是 **报功 → 核功 → 人类批准 → 记功 → 授衔 → 周报**。每一步都留有可追溯的材料。

## 用军衔组织团队，把决定留在人类手里

统筹者负责归集与登记，军务官负责核功和独立对账，业务机器人继续在原岗位交付。元帅是可由人类另行特授给统筹者的头衔，全队最多一席；它与普通军衔分别记录，不赠分，不重置普通军衔的任职时间，也不增加自批权。

同一成果只有一个分池，参与者按证据分摊。迟报沿用成果最初所属周，超出个人当周获奖上限的份额实记零。军务官自己的贡献或双方共同关联事项交人类处理，避免由机器人互相批准。

每周三份文档让你了解成果与队伍状态：**军功周报**列交付、采用、记功和授衔；**待复核清单**列缺证、待批和已批未登记事项；**团队岗位观察**整理可复用资产、重复劳动和职责缺口。岗位调整作为单独建议，优先复用现有岗位。

## 从一轮虚构演练开始

项目提供中英双语 Skill、九份模板和可选 Python 核算器。两种语言采用相同的 0.2.0 数值规则。虚构演练覆盖六步、协同分摊、超出上限、利益回避、已批未登记和独立授衔，便于先看懂制度，再配置自己的业务目标与团队。

当前接入方式是 GrokBot 文档工作流。脚本辅助核算与一致性检查；事实核验和真实人类批准仍需保留来源。自动建岗、真实改名、平台权限隔离和 routine 配置不属于本版已实现能力，复杂更正与处分使用人工模板。
